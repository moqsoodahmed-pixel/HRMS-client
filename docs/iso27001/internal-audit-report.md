# Internal Audit Report — DutyLaunch HRMS ISO/IEC 27001:2022 Readiness

Document Owner: [SECURITY OWNER] · Approved by: [APPROVER] · Audit Date: 2026-08-30 · Version: 1.0

## 1. Audit context and independence statement

This audit was performed by an AI coding assistant (Claude, via Claude Code) at the direct request of the repository owner, working through the actual source code, live test execution, and dependency scanning of the DutyLaunch HRMS application. **This is not an independent third-party ISO/IEC 27001 audit** (see Statement of Applicability, control 5.35 — "Independent review of information security," marked NOT IMPLEMENTED). It should be treated as a rigorous internal technical self-assessment: a useful and evidence-backed input to a real internal/external audit, not a replacement for one.

## 2. Scope

Application source code (`server/`, `client/`), its automated test suites, its npm dependency tree, and the ISMS documentation set produced in this same engagement (`docs/`, `docs/iso27001/`). Infrastructure, hosting, physical security, and organizational/HR/legal controls were explicitly out of scope for direct verification (no hosting has been decided; see Statement of Applicability).

## 3. Method

- Direct reading of relevant source files (models, controllers, middleware, routes) for every claim made below.
- Live execution of both automated regression suites against a running instance of the application and a real MongoDB database: `server/scripts/smoke-test.cjs` and `server/scripts/smoke-test-business-rules.cjs`.
- `npm audit` against both `server/` and `client/` dependency trees.
- Targeted negative testing added this session (forged-cookie rejection, spoofed-file-type rejection, security-header presence, password-field non-exposure).
- No infrastructure, network, or physical-security testing was performed (none exists to test).

## 6. Auditor's overall assessment

The application's *own* security engineering — input validation, RBAC, encryption, audit logging, error handling, mass-assignment protection — is materially stronger than is typical for a project at this stage, and the two regression suites (218 total assertions, 100% passing) provide real, re-runnable evidence rather than a one-time claim. The gaps that remain (F4, F5, F6 chiefly) are the kind every real organization must close through infrastructure and process decisions, not something an in-repository code change can complete alone. DutyLaunch HRMS is **not ISO/IEC 27001 certified and this audit does not claim otherwise** — it is, however, in a materially better and more honestly-documented position than before this engagement began.
